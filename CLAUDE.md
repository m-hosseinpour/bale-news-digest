# Bale News Digest

A bot that automatically fetches, judges the importance of, and summarizes news from a Bale messenger channel using an LLM.

## Main Flow

`main.py` → `news_collector.fetch_new_posts` (Bale public `POST https://api.ble.ir/api/v1/LoadHistory` for `ble.ir/s/<CHANNEL_SLUG>`) → `news_importance` (one LLM call: the importance that decides the send) → `news_summarizer` (summary + post link) → `bale_bot_message_sender` (send to target channel).

- There is no separate news classification: `judge_importance` is the only per-post LLM judgment and its verdict is what decides sending (a category layer existed until 2026-09-24; it cost an extra call for 76% of posts and the final decision rode on importance anyway). Output is one of `major`/`normal`/`trivial` (numeric scores measured as far less stable on the weak gateway); `MIN_IMPORTANCE` (env) is the send threshold. The prompt was rewritten on 2026-09-27 in two passes. The first forces only two things — `advertisement` is always `trivial`, and a non-important sports item (routine match or result, transfer, league or federation matter, athlete statement, sports press review, small tournament) is `trivial` — and leaves the rest to the model, no longer demoting statements/speeches/predictions/threats or enumerating a `normal` bucket. The second pass, after that loose version sent a two-year-old anniversary post, added a general strictness bar: only something NEW can be `major` (an anniversary, commemorative or archive item, or a re-telling of an old event, is `normal` at best and `trivial` when it carries no new fact), most items are not `major`, and when unsure choose the lower label. The multi-item-digest rule survives both passes. A third pass on 2026-09-30 pinned the "real consequence" to the reader — the prompt now states that the reader follows Iran and its region, and that a big story inside another country's own affairs (its domestic politics, courts, elections, science or space programme) is not `major` here unless it changes something for Iran or the region — and widened the retrospective list to cover a memoir or first-person account of something that happened earlier. That pass was driven by an audit of one day's verdicts (165 posts, 2026-09-29), where the model's own stored draws reproduced under re-runs 18 times out of 20 — so the disagreements were systematic, not gateway noise — and the strict bar had let a former US official's memoir of Operation True Promise through as `major` while demoting the US release of 40 million barrels from the strategic reserve. Measured for the free version on 46 real posts, one draw each (set in `measurements/free_gate.sids.json`, verdicts in `measurements/free_gate_after.json`): advertisements 10/10 `trivial`, routine sports 8/8 `trivial`, and 10 of 16 statements/positions the previous prompt always called `normal` came back `major`; the cost was 4 concrete events the previous prompt always sent as `major` coming back `normal` (oil above $105, the European diesel record, Turkey's advance in northern Iraq, secret tanker loading) — the old prompt's enumerations were not only caps but the positive definition of `major`, so removing them made the model swing both ways. Measured for the strictness bar on 13 posts, one draw each (`measurements/strict_gate_after2.json`, set in `strict_gate.sids.json`): both anniversary posts fell to `trivial`, advertisements stayed `trivial` 2/2, 3 of those 4 concrete events came back `major`, and the statements the free version had promoted fell back to `normal`; a real attack posted as «تصاویری از حملات جدید پاکستان…» with no stated consequence came back `normal`, which is the cost the strict bar carries. Measured for the third pass on 31 posts from 2026-09-29, two draws each (`measurements/review929_after.json`, same set before the change in `review929_before.json`, disputed set in `review929.sids.json`): all 8 control posts that should stay `major` (Hormuz ship explosion, US withdrawal from Iraq, US sanctions on Iran, Russia's nuclear threat, US tankers to Ben Gurion, the Al-Qassam commander's death, Iraq flight permits, the end of coalition presence in Iraq) held at `major` 2/2, and all 3 controls that should stay `trivial` (an advertisement, a routine sports result, newspaper front pages) held at `trivial` 2/2 — the reader anchor does not demote genuine regional news. Across the 20 disputed posts the `major` share fell from 23 of 40 draws to 16: the US official's memoir went to `normal`/`trivial`, and a Tehran construction fire, a US Justice Department recusal, CNN's suit over White House press access, the Starship test flight and a duplicate flood-warning post all stopped being sent; three misses came back up (Rosatom's new-reactor plan for Iran, Netanyahu's Abu Dhabi trip, the Al-Mayadeen report). What the third pass still gets wrong: two disputed posts stay `major` in one draw of two (the single-source Saddam Haftar rumour, the orange weather warning) and one army doctrine statement became `major`; and on foreign news the model sometimes drops all the way to `trivial` where `normal` would be the honest label, which the `major` threshold makes harmless. A verdict is a single draw on a round-robin gateway, so read each of these as a signal, not a median. The previous prompt's record, kept as history (2026-09-24, raw verdicts in `measurements/gate_v2*.json`, 112 posts / 138 verdicts): of 21 advertisement verdicts none came back `major`; of 34 verdicts on posts the old pipeline sent, 29 stayed `major` and 5 were demoted to `normal` (single draw each on a round-robin gateway, so those 5 are a signal, not a median — one of them came back `major` on a later draw), and a demoted post is terminal because it is still persisted as seen. The closing output-format line was spot-checked on 8 real posts on 2026-09-24: 6/6 advertisements `trivial`, 2/2 previously-sent majors still `major`. A post whose judgment *failed* keeps `importance=None` and is **sent** (fail-open) — with no category veto left, that is the only leak channel, and it applies to every topic including advertisements; a content-free post (emoji/link only) is not that case: the collector records it as `trivial`, so it is dropped. Every unusable-answer failure — in the importance judge and in the summarizer alike — logs the raw model answer and `finish_reason` via `describe_answer` in `open_ai_client_provider.py` (added 2026-09-25, after a combo backend returned responses truncated at 4096 tokens with no usable label and the leak was undiagnosable after the fact): retries only help against a random bad answer, because the router is sticky per connection and all 4 attempts of a post hit the same backend — 9 of that day's 33 posts went to the channel unjudged within one 3-hour window.

- Already-seen posts are persisted in `news_posts.json` (keeps the last `MAX_STORED_POSTS`, default 5000). `sid` is exactly `f"{rid}-{date}"` as returned by the API (`rid` is a JSON string, may be a negative int64) — changing it would re-send every post.
- The channel's internal peer id comes from `PEER_ID` in `.env` and is never re-discovered at runtime; `scripts/resolve_peer_id.py` prints it once.
- Each post that passes the importance gate is summarized individually and sent to the main channel (`BALE_BOT_CHAT_ID`) only — there are no per-category channels and no routing to decide. A run collects **all** its new posts first and then sends them oldest→newest (chronological order in the channel, added 2026-09-28); the fetch itself stays newest→oldest because that is what keeps the seen-boundary single in `fetch_new_posts`.
- If the post carries an attachment, it is sent with the summary via `sendPhoto`/`sendVideo`/`sendAudio`/`sendDocument` using the `documentMessage.url` — Bale downloads it server-side, so nothing is uploaded by us. Media has no `file_id` (LoadHistory doesn't return one) and `copyMessage`/`forwardMessage` is impossible (bot has no access to the source channel).
- Message text is sent as plain text; only the last line is a markdown link `[لینک خبر مرجع](url)`. No `parse_mode` is set.

## Common Commands

```shell
uv sync
uv run python main.py                                # one collect/summarize run
uv run pytest                                         # unit tests (no network)
uv run python scripts/resolve_peer_id.py akharinkhabar # print the channel's PEER_ID
uv run python scripts/verify_collector.py             # message-kind / dedup sanity check
uv run flask --app bot_webhook run --port 8001        # webhook (dev)
uv run gunicorn --bind 127.0.0.1:8001 bot_webhook:app  # webhook (prod)
uv run python set_webhook.py                         # register the webhook
```

## Code Style Notes

- Type hints throughout; pydantic v2 for models and validation.
- LLM prompts live as `IMPORTANCE_SYSTEM_PROMPT` in `news_importance.py` and `SYSTEM_PROMPT` in `news_summarizer.py`.
- The LLM is expected to return exactly one label or a structured summary; any prompt change must be verified against several real samples.
- File I/O errors in `utils.py` are logged, not raised — fall back to an empty list. Network/API calls in `news_collector.py` are the opposite: logged **and raised**, never swallowed into an empty list.
- The `LoadHistory` API is undocumented and returns a fixed page of 10 messages. Text for `documentMessage` lives at `message.documentMessage.caption.text` (the majority of this channel's posts) — reading only `textMessage` silently drops most news. Pagination anchor is `min(date) - 1`; the `-1` is mandatory.
