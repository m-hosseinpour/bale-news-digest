# Bale News Digest

دریافت خودکار اخبار از کانال بله، سنجش اهمیت و خلاصه‌سازی با هوش مصنوعی، و ارسال خلاصه به کانال بله.

## امکانات

- جمع‌آوری پیام‌های جدید کانال از API عمومی وب بله (بدون مرورگر)
- سنجش اهمیت هر خبر با یک فراخوانی LLM (`major`/`normal`/`trivial`)
- خلاصه‌سازی اخبار مهم و ارسال به کانال با بات بله
- ارسال عکس/ویدیو/صوت/فایل همراه خلاصه، بدون دانلود یا آپلود سمت ما
- ارسال آلبوم چند عکسی/ویدیویی به‌صورت یک پیام (`sendMediaGroup`)، همان‌طور که در کانال مبدأ است
- ذخیره پیام‌های دیده‌شده در `news_posts.json`
- Webhook برای پاسخ ثابت به پیام‌های خصوصی ربات

## پیش‌نیازها

- Python 3.11+
- uv

نیازی به مرورگر، Chromium یا Playwright نیست: جمع‌آوری از طریق
`POST https://api.ble.ir/api/v1/LoadHistory` انجام می‌شود.

## نصب پروژه

```shell
uv sync
cp .env.example .env
```

## تنظیمات `.env`

حداقل مقادیر لازم:

```env
BALE_BOT_TOKEN=
BALE_BOT_CHAT_ID=
OPEN_AI_API_KEY=
CHANNEL_SLUG=akharinkhabar
PEER_ID=533692756
```

### پیدا کردن `PEER_ID`

آیدی داخلی کانال در API بله **با آیدی Bot API یکی نیست** و باید یک‌بار استخراج شود.
اسکریپت زیر این کار را انجام می‌دهد:

```shell
uv run python scripts/resolve_peer_id.py akharinkhabar
```

خروجی چیزی شبیه این است:

```text
✓ آیدی داخلی کانال akharinkhabar: 533692756
این خط را در .env بگذار:
PEER_ID=533692756
```

همان خط را در `.env` کپی کن. ربات در زمان اجرا دیگر این مقدار را دوباره کشف نمی‌کند؛
اگر `PEER_ID` تنظیم نشده باشد، اجرا با یک خطای واضح فارسی متوقف می‌شود.

`CHANNEL_SLUG` نام عمومی کانال است و هم برای ساخت لینک خبر و هم برای حذف امضای
تبلیغاتی کانال از متن استفاده می‌شود.

### سایر کلیدهای اختیاری

```env
MAX_PAGES_PER_RUN=50      # سقف صفحه در هر اجرا (هر صفحه ۱۰ پیام)
MAX_POSTS_PER_RUN=500     # سقف پست جدید در هر اجرا
MAX_STORED_POSTS=5000     # چند پست در news_posts.json نگه داشته شود
HISTORY_PAGE_SLEEP=0.3    # مکث بین صفحه‌ها (ثانیه)
HTTP_TIMEOUT=30           # timeout درخواست‌ها (ثانیه)
```

### سرویس LLM

هر endpoint سازگار با OpenAI کار می‌کند؛ هر سه مقدار از `.env` خوانده می‌شوند و
مقدار نمونه‌شان در `.env.example` هست:

```env
OPEN_AI_BASE_URL=    # آدرس پایهٔ سرویس
OPEN_AI_MODEL_NAME=  # شناسهٔ مدل روی همان سرویس
OPEN_AI_API_KEY=
```

برای اشتراک **OpenCode Go** آدرس پایه `https://opencode.ai/inference/go/openai/v1`
است، مدل با شناسهٔ همان فهرست (`curl https://opencode.ai/inference/go/v1/models`) و
کلید از Console وُرک‌اسپیس. مدل‌های `*-free` بیرون از خود OpenCode پاسخ ۴۰۳ می‌دهند.
Go برای agentهای کدنویسی ساخته شده و ترافیک را برای سوءاستفاده پایش می‌کند؛ این
ربات هم بار کمی دارد، ولی استفاده‌اش همان استفادهٔ معمول Go نیست.

`open_ai_client_provider.py` همراه هر درخواست یک `User-Agent` با نام همین
برنامه (`bale-news-digest/1.0`) و شناسهٔ ثابت `x-opencode-session` می‌فرستد، که
Go برای مسیریابی و کش پرامپت می‌خواهد؛ بقیهٔ providerها به این دو نیازی ندارند.

### فیلتر اهمیت

هر پست **یک** فراخوانی LLM می‌گیرد و همان تصمیم ارسال را می‌سازد: اگر اهمیتش
به آستانه برسد به کانال می‌رود، وگرنه نه. دستهٔ خبری جداگانه‌ای سنجیده نمی‌شود
(قبلاً یک فراخوانی برای دسته و یک فراخوانی دیگر برای اهمیتِ دسته‌های مهم بود؛
~۴۳٪ فراخوانی کمتر).

```env
MIN_IMPORTANCE=major      # major | normal | trivial
```

پرامپت اهمیت دو چیز را از پیش پایین می‌آورد: تبلیغ همیشه `trivial` است (هر شکل
پروموشن، حتی با لحن خبری یا رسمی)، و خبر ورزشی غیرمهم `trivial` — مسابقه و
نتیجهٔ روتین، نقل‌وانتقال، امور لیگ و فدراسیون، اظهارنظر بازیکن، مرور
مطبوعات ورزشی و تورنمنت کوچک؛ فقط خبر واقعاً بزرگ ورزشی (دستاورد تاریخی ملی،
یا فاجعهٔ ورزشی) می‌تواند بالاتر برود. دو دسته را هم از پیش بالا می‌برد: خبر
جنگ در ایران و منطقه — رویداد تازهٔ نبرد و بیانیهٔ مقام ارشد دربارهٔ آن — و
تیتر بزرگ جهانی؛ هر دو همیشه `major`. **بقیهٔ قضاوت با خود مدل
است.** یک سختگیری کلی هم دارد: فقط
چیزِ **تازه** می‌تواند `major` باشد، پس گذشته‌نگر — پست سالگرد یا بزرگداشت،
مطلبی که «به مناسبت …» منتشر شده، آرشیو، و بازگویی یا خاطرهٔ اول‌شخص از واقعهٔ
قدیم — در بهترین حالت `normal` است و اگر واقعیت تازه‌ای نداشته باشد `trivial`؛
بیشتر خبرها `major` نیستند و در شک باید برچسب پایین‌تر را گرفت. اگر متنی چکیدهٔ
چند خبر باشد (مثل «آخرین خبرهای کوتاه»)، اهمیت مهم‌ترین خبرِ داخلش ملاک است.

پرامپت به خواننده **لنگر** هم دارد: خواننده ایران را دنبال می‌کند — امنیت، جنگ
و مذاکره، اقتصاد و قیمت‌هایی که می‌پردازد — و منطقه، و خبرهای بزرگ جهان را هم.
پس «پیامد واقعی» یا پیامد برای همین خواننده است یا خبری در اندازهٔ جهان: جنگ یا
درگیری بین دولت‌ها یا گروه‌های مسلح بیرون منطقه، حمله یا گروگان‌گیری بزرگ،
نتیجهٔ انتخابات یا تغییر دولت در کشور بزرگ (خودِ نتیجه، حتی وقتی معترض دارد)،
توافق/نشست/شکاف دیپلماتیک بزرگ، شوک اقتصادی یا بازار جهانی، فاجعهٔ طبیعی
پرتلفات، حادثهٔ هسته‌ای/شیمیایی/سایبری بزرگ، نقطهٔ عطف علمی یا فضایی، یا مرگ
چهرهٔ جهانی که معادلات را عوض کند. ملاک، تیترهای اصلی روزِ جهان است، نه هر
گزارش خارجی: روز عادی یک جنگ جاری، سیاست داخلی روتین، پروندهٔ قضایی معمولی،
اعتراض کوچک، جرم محلی، سلبریتی و ورزش، اعلان محصول/فناوری، حادثهٔ جزئی و تحرک
نظامی روتین یک کشور زیر `major` می‌ماند — ولی نتیجهٔ انتخابات ملی یا تغییر دولت
در کشور بزرگ، حتی وقتی معترض دارد، سیاست داخلی روتین نیست. «بزرگ» یعنی خوانندهٔ آگاه در هر جای
جهان آن را یکی از خبرهای اصلی روز بداند، نه فقط پرسروصدا یا پر بازدید.

یک استثنای دیگر هم دارد: **خبر جنگ**. هر رویداد تازهٔ نبرد در ایران یا منطقه — حمله،
گلوله‌باران، تیراندازی یا درگیری، موشک یا پهپاد شلیک‌شده یا ساقط‌شده،
جابه‌جایی نیرو و شناور، تلفات و خسارت نبرد، و آتش‌بس یا نقض آن — همیشه `major`
است، هرچند گزارش کوتاه باشد یا پیامدش را ننویسد؛ خودِ درگیری پیامد برای این
خواننده است. ملاک این است که متن خبر بدهد نبرد «چه کرد»: ادعای یک‌طرفهٔ یک
سخنگو که حمله/رهگیری/آتش‌بس رخ داده هم همان رویداد است، ولی تکذیب و
گذشته‌نگر جنگی (خاطره، سالگرد، مرور جنگ) زیر همان قاعدهٔ عمومی می‌مانند.

بیانیه هم حساب دارد: هر حرف تازهٔ یک مقام ارشد دربارهٔ جنگِ ایران و منطقه — رئیس
کشور یا دولت (رئیس‌جمهور، نخست‌وزیر، پادشاه، رهبر)، وزیر خارجه یا دفاع، فرماندهٔ
ارشد، سخنگوی رسمی، یا رهبر گروه مسلح درگیر، از ایران یا کشورهای منطقه یا گروه
مسلح درگیر یا قدرت بزرگ دخیل — حتی وقتی فقط حرف است (موضع، هشدار، تهدید،
وعدهٔ پاسخ، شرط، تصمیم) `major` است. کسی که الان چنین مقامی دارد حتی اگر روحانی
هم باشد حساب می‌شود؛ کسی که تنها ادعایش مقام گذشته است نه. هر صدایی مقام نیست:
نمایندهٔ مجلس، روحانیِ بی‌مقام، کارشناس، خبرنگار و تحلیلگر، تکرار حرف قدیمی،
نقل‌قول بی‌منبع و تفسیر حرف دیگران زیر قاعدهٔ عمومی می‌مانند.

- `major`: خبری که خوانندهٔ کم‌وقت باید همین حالا بداند، حتی اگر فقط یک خبر
  بخواند.
- `normal`: ارزش دانستن دارد ولی فوری نیست.
- `trivial`: واقعاً خبر نیست.

**«حالا» به مدل داده می‌شود** (۲۰ نوامبر ۲۰۲۶): هر دو پرامپت — اهمیت و خلاصه —
در ابتدای پیام system یک بلوک متادات می‌گیرند («این پست در ۲۸ آبان ۱۴۰۵، ساعت
۱۷:۵۳ به وقت تهران (2026-11-19) منتشر شده»). تاریخ از `date` خودِ API بله می‌آید
(بخش دوم `sid`)، نه از ساعت اجرا، پس در اجرای دوباره هم ثابت است. بلوک صریحاً
«متادیتا، نه متن خبر» اعلام می‌شود و هرگز داخل پیام کاربر نمی‌رود. دلیلش:
بدون تاریخ، مدل نمی‌تواند تاریخِ داخل متن را با «حالا» بسنجد؛ پستی که «ویدیوی
تازه از حملهٔ ۱۷ فروردین ۱۴۰۵» را منتشر می‌کرد هم `major` شد و هم خلاصه‌اش به
گزارشِ خودِ حمله تبدیل شد. با تاریخ، بند گذشته‌نگر گیت «انتشار تازهٔ فیلم/تصویر
رویدادی که خیلی پیش‌تر افتاده» را هم پوشش می‌دهد؛ تصاویر رویداد یک‌روزه (که با
این قید پوشش داده نمی‌شوند) دست‌نخورده می‌مانند.

اندازه‌گیری ۲۷ سپتامبر، هر کدام یک قرعه:

- بدون بند سختگیری، ۴۶ پست (`measurements/free_gate_after.json`): تبلیغ ۱۰/۱۰ و
  ورزشی روتین ۸/۸ `trivial` ماندند، ۱۰ از ۱۶ بیانیه `major` شد، ولی ۴ رویداد
  مشخص (عبور نفت برنت از ۱۰۵ دلار، رکورد گازوئیل اروپا، پیشروی ترکیه در شمال
  عراق، بارگیری مخفی نفت‌کش‌ها) که پرامپت قبلی همیشه `major` می‌فرستاد `normal`
  برگشتند.
- پس از افزودن بند سختگیری، ۱۳ پست (`measurements/strict_gate_after2.json`): هر
  دو پست سالگرد (که پیش‌تر `major` رفته بودند) `trivial` شدند، تبلیغ ۲/۲ `trivial`
  ماند، ۳ رویداد از آن ۴ برگشتند و بیانیه‌های صعودکرده به `normal` برگشتند.
  هزینه: گزارشی مثل «تصاویری از حملات جدید …» که پیامدش را در متن نمی‌گوید
  `normal` می‌شود.
- پس از افزودن لنگر خواننده و بند خاطره، ۳۱ پست ۷ مهر با دو قرعه
  (`measurements/review929_before.json` و `review929_after.json`): هر ۸ پست
  کنترلِ `major` و هر ۳ کنترلِ `trivial` دست‌نخورده ماندند؛ روی ۲۰ پست مورد
  اختلاف `major` از ۲۳ قرعه از ۴۰ به ۱۶ افتاد — ۶ ارسال زائد پایین آمد (روایت
  مک‌گورک، آتش‌سوزی تهران، کناره‌گیری مقام دادگستری آمریکا، دعوای CNN با کاخ
  سفید، استارشیپ (که بند ششم اگر نقطهٔ عطف جهانی باشد دوباره می‌فرستد)، هشدار سیلاب) و ۳ جاماندهٔ مشخص بالا آمد (نیروگاه روساتم، سفر
  نتانیاهو به ابوظبی، گزارش المیادین). باقی‌مانده: دو پست هنوز در یک قرعه از دو
  قرعه `major` می‌شوند و یک بیانیهٔ دکترینی ارتش هم `major` شد.
- پس از افزودن بند جنگ (۱۶ نوامبر ۲۰۲۶)، ۲۰ پست با دو قرعه
  (`measurements/war_gate.sids.json`، قبل `war_gate_before.json`، بعد
  `war_gate_after.json`): ۷ از ۸ رویداد جنگی که `normal` بودند (حملهٔ موشکی یمن به
  مواضع سعودی، درگیری کرکوک، گلوله‌باران جنوب لبنان، انهدام انبارهای سعودی،
  انهدام تیم پژاک در مرز، ساقط‌شدن پهپاد در غرب ایران و «صدای انفجار» قشم) در هر
  دو قرعه `major` شدند؛ ۳ تهدید لفظی، تبلیغ، ورزش و جنگ اوکراین تکان نخوردند،
  هیچ گذشته‌نگر جنگی `major` نشد (یکی یک قرعه پایین‌تر رفت) و ۲ کنترل `major` هم
  `major` ماند. تنها جامانده انفجار بی‌توضیح بغداد بود. هزینه: «صدای انفجار»
  تأییدنشده در ایران حالا `major` می‌شود. در یک سنجش تکی روی ۵ پست دیگر
  (`measurements/war_gate_probe_after.json`) ۲ پست بالا رفت: حملهٔ تازه به رادار
  آمریکا در بحرین (درست) و پوشش تصویری عملیات یمن در مأرب که تازه‌بودنش از متن
  معلوم نیست — یعنی ۱ از ۳ پست تصویریِ گذشته‌نگر بالا رفت؛ تصاویر خرابه‌های قدیمی و
  انفجار کارخانهٔ ترکیه `normal` ماندند.
- پس از بازبینی، جملهٔ «even when it is one-sided» تیزتر شد تا ادعای یک‌طرفه
  دربارهٔ رویدادی که رخ داده با تهدید/پیش‌بینی/تحلیل/تکذیب قاطی نشود. بازآزمون
  روی ۱۱ پست یک قرعه (`measurements/war_gate_recheck_after.json`) همان الگو را
  داد: ادعای یک‌طرفهٔ یمن `major`، بیانیه‌ها `normal`، تبلیغ و ورزش `trivial`،
  حملهٔ تازهٔ بحرین `major`، و هیچ پست تصویریِ گذشته‌نگر — مأرب، پایگاه سلطان،
  ویرانهٔ پایگاه‌های آمریکا — `major` نشد. دو مورد مبهم با دو
  قرعهٔ بیشتر (`war_gate_recheck_after2.json`): «صدای انفجار» قشم ۲ از ۳ `major` و
  انفجار بی‌توضیح بغداد ۲ از ۳ `normal`.
- پس از افزودن قاعدهٔ بیانیه (۱۷ نوامبر ۲۰۲۶)، ۱۸ پست با دو قرعه
  (`measurements/war_stmt.sids.json`، قبل `war_stmt_before.json`، بعد
  `war_stmt_after.json`): ۷ از ۸ بیانیهٔ مقام ارشد (تهدید رضایی به پایگاه‌های
  اروپایی، برداشتن محدودیت‌ها، عبداللهی زیر بمباران، حیدری و قرارگاه ناوها،
  ایزدی، سخنگوی ارتش و عراقچی «فراتر از ایران») از `normal` ۲/۲ به `major` ۲/۲
  رفت. هشتم، حرف نعیم قاسم دربارهٔ بهانه‌های هسته‌ای (نه دربارهٔ نبرد)، فقط یک قرعه
  از دو `major` شد و در واژگان بعدی `normal` ۲/۲ ماند. هیچ‌کدام از ۵ صدای غیرمقامی
  (پنس و بلینکنِ سابق، نمایندهٔ کنگره، کارشناسان چینی، تحلیل آتلانتیک) `major`
  نشدند و گذشته‌نگر، تبلیغ، ورزش، اوکراین و کنترل `major` هم جابه‌جا نشدند. در
  قرعهٔ نگهبان روی ۱۲ پست جنگی (`war_stmt_guard_after.json`) از ۹ رویداد، ۸ همان
  `major` ماندند و فقط انفجار بی‌توضیح بغداد `normal` شد؛ دو تهدید فرماندهٔ ارشد
  (ایزدی، رضایی) `major` شدند و حرف پنس (معاون سابق) `normal` ماند. با واژگان
  نهایی، همان نگهبان یک قرعه (`war_stmt_guard_final.json`) ۱۱ از ۱۲ را `major` داد
  و این بار بغداد هم `major` شد — همان مورد مبهم همیشگی.
- پس از بازکردن دامنهٔ مقام‌ها به رئیس کشور/دولت و رهبر گروه مسلح و قاعدهٔ تقدم
  بر روحانی، ۶ پست رئیسان و وزرا با دو قرعه (`war_stmt2_before.json` /
  `war_stmt2_after.json`) سنجیده شد: نخست‌وزیر انگلیس `major` ۲/۲ (پیش از این هم
  بود و با واژگان نهایی دوباره سنجیده نشد)، رهبر انقلاب از `major`/`normal` به
  `major` ۲/۲، لاوروف دربارهٔ ایران `major` ۱ از ۲؛ در عوض نخست‌وزیر اسپانیا
  (کشور بیرون منطقه و غیردخیل) `normal` ۲/۲ و لاوروف دربارهٔ اوکراین `normal` ۲/۲.
  زیر واژگان نهایی ۸ پست سنجیده شد — ۵ پست از همان ۶ تا به‌علاوهٔ قاسم، پنس و تبلیغ
  به‌عنوان کنترل (`war_stmt3_after.json`) — و دو بیانیهٔ اردوغان دربارهٔ همین جنگ
  `major` ۲/۲ شد (`war_stmt4_after.json`)، یعنی شاخهٔ رئیس دولتِ منطقه کار می‌کند.
  پست نتانیاهو زیر `major` ماند، ولی دلیلش جغرافیا نیست: خودِ کانال آن را «عملیات
  روانی انتخاباتی» توصیف کرده و در واژگان میانی یک قرعه `major` شده بود؛ قید «حرف
  تازه/رویداد تازه» آن را پایین نگه داشته است.
- پس از دادن تاریخ انتشار به پرامپت (۲۰ نوامبر ۲۰۲۶)، ۱۰ پست با دو قرعه: پست
  «ویدیوی تازه از حمله به پتروشیمی جم» از `major` ۲/۲ به `normal`/`trivial` رفت —
  همان موردی که گزارش شد، و متنش رویداد را ۷ ماه قبل تاریخ‌گذاری می‌کرد. تصاویر
  تازهٔ یک درگیری یک‌روزه (یمن) تکان نخوردند (`normal`/`major` در هر دو شاخه)،
  آتش‌سوزی جاری نفتکش و هر ۳ رویداد تازهٔ جنگ `major` ۲/۲ ماندند و تبلیغ و ورزش
  `trivial` ۲/۲. هزینهٔ باقی‌مانده: تصاویر جزیرهٔ راداری در یک قرعه از دو `normal`
  شد؛ با دو قرعه نمی‌شود گفت سیستماتیک است یا نویز گیت‌وی.
- پس از افزودن بند تیتر بزرگ جهانی (۲۱ نوامبر ۲۰۲۶)، بازبینی ۱۹۴ پست ۲۹ و ۳۰ آبان
  نشان داد هر ۳۸ ارسال ایران/منطقه بود و هیچ خبر جهانیِ غیرمنطقه‌ای نرفت؛ تنها
  جاماندهٔ قطعی موشک روسی به لهستان بود که ذخیره‌اش `normal` بود ولی با پرامپت
  قبلی `major` ۲/۲ شد (قرعهٔ بد، نه نقص). ریزش ۲٫۵ تریلیون دلاری بورس آمریکا، افت
  ۵٪ نیکی، طرح آمریکا برای اوکراین/ناتو و هک NCIC سیستماتیک `normal` بودند. سنجش
  ۲۰ پست با دو قرعه (`measurements/world_news_after.json` و
  `world_news_after2.json`): هر ۵ تیتر جهانی هدف `major` ۲/۲؛ ادعای هک انویدیا و
  حملهٔ روتین اودسا `normal` ۲/۲؛ ۳ کنترل `major` ایران/منطقه و تبلیغ و ورزش
  دست‌نخورده؛ هیچ کنترل غیرمهمی `major` نشد. سنجش مکمل (`world_news_after3.json`):
  سه پست اپک — شروع نشست، پایان ۹۰ دقیقه‌ای و بیانیهٔ چهارماده‌ای — `major` ۲/۲
  شدند، ولی «بیانیهٔ مشترک ندادند» `trivial`/`normal` و «ترک شنزن» `trivial` ۲/۲
  ماندند (۳ پست از ۵ پست اپک major شد، نه سیل)، ولی نتیجهٔ انتخابات برزیل
  `trivial` ۲/۲ آمد. یک جمله اضافه شد که
  نتیجهٔ انتخابات/تغییر دولت در کشور بزرگ با «سیاست داخلی روتین» اشتباه نشود؛ در
  بازآزمون نهایی (`world_news_final.json`، `world_news_final2.json`،
  `world_news_elections.json`) هر ۵ تیتر جهانی، نشست اپک، نتیجهٔ انتخابات
  میان‌دوره‌ای آمریکا و بیانیهٔ لولا `major` ۲/۲ ماندند و کنترل MQ-9، تبلیغ،
  اودسا و مکزیک تکان نخوردند (ورزش و کنترل‌های دیگر در سنجش قبلی دست‌نخورده
  بودند)؛ تنها استثنا همان پست «لولا رئیس‌جمهور
  برزیل شد» است که با وجود جملهٔ صریح `trivial` ۲/۲ ماند (احتمالاً چون مدل آن را
  بازگویی انتخاب ۲۰۲۲ می‌خواند) — یک لبهٔ باقی‌مانده، نه شکاف سیستماتیک. هزینه:
  خطر «تعطیلی دولت آمریکا» یک قرعه از دو `major` شد.

اگر سنجش اهمیت شکست بخورد (پاسخ خالی/بی‌ربط مدل)، پست **فرستاده می‌شود**
(fail-open) تا خبر بی‌صدا از دست نرود.

### خلاصه‌سازی چکیده‌ها

پست چکیده («آخرین خبرهای کوتاه») فهرستی از چند خبر جداست، نه یک خبر. خلاصه‌ساز
از این فهرست فقط خبرهایی را می‌آورد که به معیار `major` می‌خورند و هر خبر را در
یک خط جدا می‌نویسد:

- خبرهای کم‌اهمیت چکیده (اظهارنظر، ادعا و تکذیب، پیش‌بینی، دیدار، نتیجهٔ
  مسابقه، هوا، ترافیک، عوارض، دستگیری، اطلاعیهٔ اداری، تغییر جزئی قیمت) در
  خلاصه نمی‌آیند.
- هدر چکیده، بولت‌ها، ایموجی‌ها و خط امضا/تبلیغ خبر نیستند و در خلاصه نمی‌آیند —
  در چکیده قانون ۶ (برگرداندن متن ورودی دست‌نخورده) اعمال نمی‌شود.
- اگر هیچ خبری از این صافی رد نشود، فقط مهم‌ترین خبر چکیده در یک خط می‌آید؛
  خروجی هیچ‌وقت خالی نمی‌شود. تنها استثنا فهرستی است که تمامش تبلیغ و خط
  تبلیغاتی است: در آن حالت فقط نام چیزی که تبلیغ می‌شود می‌آید، بدون قیمت،
  هندل، لینک و فراخوان اقدام.
- اگر متن یک خبر پیوسته باشد (نه فهرست) — حتی اگر روی چند خط شکسته شده باشد —
  همان پاراگراف فشرده نوشته می‌شود و به خط‌ها شکسته نمی‌شود.

صافیِ چکیده در خلاصه‌ساز («رویدادی که رخ داده») از معیار `major` گیت **سخت‌گیرانه‌تر**
است: گیت از ۲۷ سپتامبر موضوع را از پیش پایین نمی‌برد و از ۱۶–۱۷ نوامبر خبر
جنگ (رویداد تازه و بیانیهٔ مقام ارشد) و از ۲۱ نوامبر تیتر بزرگ جهانی را از پیش
بالا می‌برد، ولی این صافی هنوز بیانیه/موضع/دیدار را از خلاصه کنار
می‌گذارد. پس پستی که به‌خاطر یک بیانیه `major` شده و رفته، اگر چکیده باشد همان
بیانیه را فقط در خط fallback («مهم‌ترین خبر») می‌آورد. انتخاب مستقل از گیت است و
این تفاوت عمدی است.

### پست‌هایی که خبرشان «انتشار فیلم/تصویر» است

اگر خودِ متن پست بگوید فیلم یا تصویر تازه‌ای از رویدادی منتشر شده («ویدیوی جدید
از لحظه …»، «تصاویری از …»، «فیلم …»)، خبر همان انتشار است، نه رویداد: خلاصه با
انتشار شروع می‌شود و اگر متن تاریخ رویداد را داده باشد نگهش می‌دارد، تا رویداد
«همین حالا» خوانده نشود. این تنها استثنای قانون ۵ (ممنوعیت اشاره به ضمیمه) است و
فقط به ادعای خودِ متن وابسته است؛ برچسبِ ضمیمه (`[این خبر همراه یک ویدیو است.]`)
چنین ادعایی نیست، پس پست متنیِ دارای ویدیو همچنان بدون اشاره به فیلم خلاصه می‌شود.
تاریخ انتشار پست هم مثل گیت در system داده می‌شود (بالا) ولی هرگز در خلاصه نمی‌آید.

سنجش ۲۰ نوامبر ۲۰۲۶ (۵ پست تصویری × ۲ قرعه، قبل/بعد، به‌علاوهٔ ۳ کنترل):
هر ۱۰ خلاصهٔ شاخهٔ جدید با «انتشار/ویدیوی تازه…» شروع شدند و خلاصهٔ پتروشیمی جم
تاریخ رویداد (۱۷ فروردین) را نگه داشت؛ ۳ کنترل (خبر متنی، چکیده، تبلیغ) هیچ اشارهٔ
تازه به فیلم/تصویر و هیچ تاریخ متاداتی نگرفتند و ۲ پست متنیِ دارای ویدیو (بیانیهٔ
فرمانده سپاه) هم دست‌نخورده ماندند. هزینه: خلاصهٔ پست‌های تصویری از ۴ تا ۹۵
کاراکتر بلندتر شد (میانه ~۴۴؛ یک قرعه کوتاه‌تر).

اگر از webhook ربات استفاده می‌کنی:

```env
PUBLIC_WEBHOOK_URL=https://your-domain.com/webhook
```

همهٔ پست‌های مهم فقط به کانال اصلی (`BALE_BOT_CHAT_ID`) ارسال می‌شوند؛
کانال اختصاصی برای دسته‌ها وجود ندارد و تنها معیار ارسال، آستانهٔ اهمیت است.

ترتیب ارسال، ترتیب زمانِ خبر است: هر ران اول کل خبرهای تازه را جمع می‌کند و
بعد از قدیمی‌ترین به جدیدترین می‌فرستد. واکشی برعکس است (جدیدترین→قدیمی‌ترین)،
چون همان ترتیب است که «تا کجا دیده‌ایم» را یکتا نگه می‌دارد؛ اگر معکوس‌کردن را
برداریم، پستی که قبلاً خوانده‌ایم جلوی بقیهٔ همان صفحه را می‌گیرد.

## تست‌ها

تست‌های واحد به شبکه کاری ندارند:

```shell
uv run pytest
```

برای بررسی سلامت جمع‌آوری روی داده واقعی (شمارش نوع پیام‌ها و نرخ تطبیق `sid`
با `news_posts.json`):

```shell
uv run python scripts/verify_collector.py        # ۱۰۰ پیام آخر
uv run python scripts/verify_collector.py 300    # یا هر تعداد دلخواه
```

برای سنجش اثر یک تغییر در پرامپت خلاصه‌ساز، طول خلاصه روی نمونه‌ای از
پست‌های واقعی اندازه‌گیری می‌شود (طول، تعداد جمله، و نرخ حفظ عددهای متن اصلی).
اول نمونه را با پرامپت فعلی فریز کن، بعد از تغییر پرامپت همان نمونه را دوباره
بسنج:

```shell
uv run python scripts/measure_summary_length.py --out measurements/before.json --save-sids measurements/sample.sids.json
# پس از ویرایش پرامپت:
uv run python scripts/measure_summary_length.py --out measurements/after.json --sids measurements/sample.sids.json
```

فریزکردن نمونه لازم است: `news_posts.json` هر ۱۵ دقیقه با اجرای تایمر رشد
می‌کند و بدون فهرست `sid`، نمونهٔ تصادفی بین دو اجرا جابه‌جا می‌شود و مقایسه
بی‌جفت می‌ماند. گیتوی مدل‌ها را round-robin می‌کند، پس نتیجه نویزی است و باید با
میانه مقایسه شود، نه با یک اجرا.

## سرویس systemd (سطح کاربر)

سرویس‌ها **سطح کاربر** اجرا می‌شوند، نه روت: ری‌استارت دیگر `sudo` نمی‌خواهد و اکشن
دیپلوی با `systemctl --user` کار می‌کند. یونیت‌ها در `deploy/user/` نسخه‌بندی شده‌اند و
دیپلوی همان‌ها را در `~/.config/systemd/user/` نصب می‌کند، پس یونیتِ مستقر از یونیتِ
کامیت‌شده جدا نمی‌افتد.

نصب (اکشن دیپلوی همین را انجام می‌دهد):

```shell
mkdir -p ~/.config/systemd/user
cp deploy/user/bale-news-digest.service \
   deploy/user/bale-news-digest.timer \
   deploy/user/news-bot-webhook.service \
   ~/.config/systemd/user/
systemctl --user daemon-reload
```

**`linger` الزامی است.** بدون آن مدیر کاربر با بسته‌شدن آخرین سشن از بین می‌رود،
تایمر و سرویس‌ها خاموش می‌شوند، و دیپلوی هم وقتی کسی لاگین نیست به bus وصل نمی‌شود:

```shell
sudo loginctl enable-linger "$USER"     # یک‌بار، با sudo
```

فعال‌کردن (بدون sudo):

```shell
systemctl --user enable --now bale-news-digest.timer
systemctl --user enable --now news-bot-webhook.service
```

بررسی وضعیت و لاگ:

```shell
systemctl --user status news-bot-webhook.service --no-pager
systemctl --user list-timers
journalctl --user -u bale-news-digest.service --no-pager
```

اگر سرویس روی سرور **قبلاً** به‌صورت روت نصب بوده، اول نسخهٔ روت را خاموش و حذف کن؛
وگرنه دو نسخه از یک سرویس با هم بالا می‌آیند (هر دو روی پورت ۸۰۰۱، و دو تایمر
۱۵ دقیقه‌ای که هر پست را دو بار پردازش می‌کنند):

```shell
sudo systemctl disable --now bale-news-digest.timer news-bot-webhook.service
sudo rm /etc/systemd/system/bale-news-digest.service \
        /etc/systemd/system/bale-news-digest.timer \
        /etc/systemd/system/news-bot-webhook.service
sudo systemctl daemon-reload
```

## نکات

- خروجی اجرا در لاگ و در `news_posts.json` ذخیره می‌شود.
- اگر مدل پاسخ خالی یا بی‌استفاده برگرداند (بعضی backendهای گیتوی به‌جای
  پاسخ، یک پیام بی‌ربط به زبان دیگر می‌دهند)، تا ۳ بار دوباره تلاش می‌شود —
  هم در سنجش اهمیت (پاسخی که هیچ برچسب معتبری ندارد) و هم در خلاصه‌ساز
  (پاسخی که فارسی نیست).
- در سنجش اهمیت، **خطای انتقالی** (timeout یا قطع اتصال گیتوی) هم مثل پاسخ
  بی‌استفاده تلاش مجدد می‌گیرد؛ فقط اگر هر ۴ تلاش (پشت سر هم، با یک ثانیه
  مکث) شکست بخورد پست با `importance=None` ذخیره و fail-open فرستاده می‌شود.
- اگر خلاصه‌ساز بعد از تلاش‌ها پاسخ قابل استفاده نگیرد، اجرا با خطا متوقف
  می‌شود و آن پست در `news_posts.json` ذخیره نمی‌شود، پس در اجرای بعدی دوباره
  پردازش می‌شود.
- اگر سنجش اهمیت بعد از تلاش‌ها پاسخ قابل استفاده نگیرد، `news_collector` آن
  استثنا را می‌گیرد و `importance=None` ذخیره می‌کند؛ در ارسال fail-open
  رفتار می‌کنیم و پست **فرستاده می‌شود**. این تنها راه نشتی است: پستی که
  قضاوت نشده (حتی تبلیغ) هنگام خرابی گیتوی می‌تواند به کانال برود. برای دیدن
  این موارد در لاگ:

  ```shell
  journalctl --user -u bale-news-digest.service --no-pager | grep -E "خطا در سنجش اهمیت|\[ \? \]"
  ```

  هر شکستِ پاسخ بی‌استفاده — چه در سنجش اهمیت و چه در خلاصه‌ساز —
  **پاسخ خام مدل و `finish_reason`** را هم لاگ می‌کند
  (`finish_reason=length | پاسخ خام: '…'`) تا معلوم شود مدل چه گفته بود؛ دیدن
  `finish_reason=length` یعنی پاسخ به سقف توکن خورده و بریده شده است.
- تلاش دوباره فقط وقتی نجات می‌دهد که بکاند خرابِ گیتوی جواب بدِ تصادفی
  بدهد. روتر به یک اتصال می‌چسبد، پس هر ۴ تلاش یک پست به همان بکاند می‌رود
  (۲۵ سپتامبر ۲۰۲۶: بکاندی پاسخ‌هایش را در ۴۰۹۶ توکن می‌بُرید و ۹ پست در یک
  پنجرهٔ ۳ ساعته بی‌داوری به کانال رفت). برای دیدن اینکه هر درخواست به کدام
  بکاند رفته:

  ```shell
  sqlite3 "file:$HOME/.9router/db/data.sqlite?mode=ro" \
    "select substr(timestamp,12,8), model, promptTokens, completionTokens
     from usageHistory where promptTokens between 550 and 850
     order by timestamp desc limit 20;"
  ```
- `sid` هر پست دقیقاً `"{rid}-{date}"` است، همان چیزی که API بله می‌دهد؛ همین
  باعث می‌شود dedup با `news_posts.json` بدون تغییر کار کند و خبری دوباره ارسال نشود.
- برای پاسخ‌دهی ربات در PV، حتماً سرور باید با HTTPS در دسترس باشد.

## ضمیمه‌ها (عکس/ویدیو/صوت/فایل)

پست‌های دارای ضمیمه همراه خلاصه ارسال می‌شوند. چند نکته:

- عکس و ویدیو در API بله هم به شکل `documentMessage` می‌آیند (نه
  `photoMessage`/`videoMessage`)؛ نوع ضمیمه از روی `mimeType` تعیین می‌شود.
- LoadHistory هیچ `file_id` نمی‌دهد — فقط `url` امضاشدهٔ عمومی. پس متد ارسال
  (`sendPhoto`/`sendVideo`/`sendAudio`/`sendDocument`) همان URL را می‌گیرد و
  **خود بله** از آن دانلود می‌کند؛ نه دانلودی سمت ما انجام می‌شود نه آپلودی.
- **آلبوم در LoadHistory یک ردیف نیست، چند ردیف پشت‌سرهم است**: ردیف‌ها ۱ تا ۷
  میلی‌ثانیه فاصله دارند و فقط قدیمی‌ترینشان کپشن دارد. ردیف‌های بی‌متن با شرط
  «متن خالی» دور می‌افتادند و از آلبوم چهار عکسی فقط یکی می‌رفت؛ حالا
  `_group_album_rows` آن‌ها را یک پست می‌کند و `sendMediaGroup` همه را در یک
  پیام می‌فرستد (کپشن روی قلم اول). گروه‌بندی روی کل ران انجام می‌شود، چون
  آلبوم ۱۰ قلمی از مرز صفحه (۱۰ ردیف) می‌گذرد.
- سقف‌های واقعی `sendMediaGroup` (تست زنده): ۱۰ قلم در هر پیام (۱۱ قلم
  «malformed request» می‌دهد)، `media` باید آرایهٔ واقعی JSON باشد نه رشتهٔ
  JSON، و کپشن تا ۴۰۹۶ کاراکتر می‌رود. آلبوم سند/صوت تست نشد و گروه نمی‌شود؛
  رفتارشان مثل قبل است (فقط ردیف دارای کپشن می‌رود).
- کپی/فوروارد سمت‌سرور (`copyMessage`/`forwardMessage`) ممکن نیست: ربات به کانال
  مبدأ دسترسی ندارد و `file_id` هم در دست نیست.
- متن خبر بدون خود ضمیمه به مدل می‌رود، ولی مدل می‌داند ضمیمه‌ای هست
  (برچسب نوعش را می‌گیرد) تا خلاصه مثل خبر عادی نوشته شود و مستقیم به
  عکس/فیلم اشاره نکند. تنها استثنا پستی است که خودِ متنش انتشار فیلم/تصویر
  تازه را خبر می‌دهد (بخش «پست‌هایی که خبرشان انتشار فیلم/تصویر است»).
- متن پیام عادی فرستاده می‌شود و فقط خط آخرش عبارت «لینک خبر مرجع» به شکل
  لینک مارک‌داون (`[لینک خبر مرجع](url)`) است؛ بله خودش آن را رندر می‌کند و
  `parse_mode` لازم نیست.
