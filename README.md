# Bale News Digest

دریافت خودکار اخبار از کانال بله، دسته‌بندی و خلاصه‌سازی با هوش مصنوعی، و ارسال خلاصه به کانال بله.

## امکانات

- جمع‌آوری پیام‌های جدید کانال از API عمومی وب بله (بدون مرورگر)
- دسته‌بندی اخبار با OpenAI-compatible API
- خلاصه‌سازی اخبار مهم و ارسال به کانال با بات بله
- ارسال عکس/ویدیو/صوت/فایل همراه خلاصه، بدون دانلود یا آپلود سمت ما
- ذخیره پیام‌های دیده‌شده در `news_posts.json`
- Webhook برای پاسخ ثابت به پیام‌های خصوصی ربات

## پیش‌نیازها

- Python 3.11+
- uv

نیازی به مرورگر، Chromium یا Playwright نیست: جمع‌آوری از طریق
`POST https://api.ble.ir/api/v1/LoadHistory` انجام می‌شود.

## نصب پروژه

```shell
uv sync
cp .env.example .env
```

## تنظیمات `.env`

حداقل مقادیر لازم:

```env
BALE_BOT_TOKEN=
BALE_BOT_CHAT_ID=
OPEN_AI_API_KEY=
CHANNEL_SLUG=akharinkhabar
PEER_ID=533692756
```

### پیدا کردن `PEER_ID`

آیدی داخلی کانال در API بله **با آیدی Bot API یکی نیست** و باید یک‌بار استخراج شود.
اسکریپت زیر این کار را انجام می‌دهد:

```shell
uv run python scripts/resolve_peer_id.py akharinkhabar
```

خروجی چیزی شبیه این است:

```text
✓ آیدی داخلی کانال akharinkhabar: 533692756
این خط را در .env بگذار:
PEER_ID=533692756
```

همان خط را در `.env` کپی کن. ربات در زمان اجرا دیگر این مقدار را دوباره کشف نمی‌کند؛
اگر `PEER_ID` تنظیم نشده باشد، اجرا با یک خطای واضح فارسی متوقف می‌شود.

`CHANNEL_SLUG` نام عمومی کانال است و هم برای ساخت لینک خبر و هم برای حذف امضای
تبلیغاتی کانال از متن استفاده می‌شود.

### سایر کلیدهای اختیاری

```env
MAX_PAGES_PER_RUN=50      # سقف صفحه در هر اجرا (هر صفحه ۱۰ پیام)
MAX_POSTS_PER_RUN=500     # سقف پست جدید در هر اجرا
MAX_STORED_POSTS=5000     # چند پست در news_posts.json نگه داشته شود
HISTORY_PAGE_SLEEP=0.3    # مکث بین صفحه‌ها (ثانیه)
HTTP_TIMEOUT=30           # timeout درخواست‌ها (ثانیه)
```

### فیلتر اهمیت

پست‌هایی که در دسته‌های مهم می‌افتند، یک بار دیگر هم از نظر اهمیت سنجیده
می‌شوند و فقط اگر به آستانه برسند به کانال می‌روند:

```env
MIN_IMPORTANCE=major      # major | normal | trivial
```

- `major`: فقط رویداد مشخصی که رخ داده و پیامد دارد (حمله، تصمیم رسمی، شوک
  اقتصادی، فاجعه). سخت‌گیرانه‌ترین حالت و کم‌ترین حجم.
- `normal`: رویداد + اظهارنظر/بیانیه/دیدار رسمی.
- `trivial`: عملاً چیزی ارسال نمی‌شود مگر خبرهای بسیار مهم.

اگر سنجش اهمیت شکست بخورد (پاسخ خالی/بی‌ربط مدل)، پست **فرستاده می‌شود**
(fail-open) تا خبر بی‌صدا از دست نرود.

اگر از webhook ربات استفاده می‌کنی:

```env
PUBLIC_WEBHOOK_URL=https://your-domain.com/webhook
```

برای هر دستهٔ مهم می‌توانی کانال اختصاصی بدهی
(`BALE_BOT_CHAT_ID_WAR_CONFLICT`, `BALE_BOT_CHAT_ID_POLITICS`,
`BALE_BOT_CHAT_ID_ECONOMY`, `BALE_BOT_CHAT_ID_SCIENCE_TECH`).

## تست‌ها

تست‌های واحد به شبکه کاری ندارند:

```shell
uv run pytest
```

برای بررسی سلامت جمع‌آوری روی داده واقعی (شمارش نوع پیام‌ها و نرخ تطبیق `sid`
با `news_posts.json`):

```shell
uv run python scripts/verify_collector.py        # ۱۰۰ پیام آخر
uv run python scripts/verify_collector.py 300    # یا هر تعداد دلخواه
```

## اجرای webhook ربات

برای توسعه:

```shell
uv run flask --app bot_webhook run --host 0.0.0.0 --port 8001
```

برای production:

```shell
uv run gunicorn --bind 127.0.0.1:8001 --workers 1 bot_webhook:app
```

بررسی سلامت سرویس:

```shell
curl http://127.0.0.1:8001/health
```

## ثبت webhook ربات

بعد از اینکه آدرس عمومی webhook با HTTPS آماده شد:

```shell
uv run python set_webhook.py
```

آدرس webhook باید به route زیر برسد:

```text
/webhook
```

## نکات

- خروجی اجرا در لاگ و در `news_posts.json` ذخیره می‌شود.
- اگر مدل پاسخ خالی یا بی‌استفاده برگرداند (بعضی backendهای گیتوی به‌جای
  پاسخ، یک پیام بی‌ربط به زبان دیگر می‌دهند)، تا ۳ بار دوباره تلاش می‌شود —
  هم در کلاسیفایر (پاسخی که هیچ برچسب معتبری ندارد) و هم در خلاصه‌ساز
  (پاسخی که فارسی نیست).
- اگر خلاصه‌ساز بعد از تلاش‌ها پاسخ قابل استفاده نگیرد، اجرا با خطا متوقف
  می‌شود و آن پست در `news_posts.json` ذخیره نمی‌شود، پس در اجرای بعدی دوباره
  پردازش می‌شود.
- اگر کلاسیفایر بعد از تلاش‌ها پاسخ قابل استفاده نگیرد، `news_collector` آن
  استثنا را می‌گیرد و دستهٔ `unknown` می‌گذارد. پست ذخیره می‌شود و چون `sid`ش
  دیده‌شده حساب می‌شود، دیگر هرگز دسته‌بندی نمی‌شود — یعنی آن خبر بی‌صدا از
  دست می‌رود. برای دیدن این موارد در لاگ:

  ```shell
  journalctl -u bale-news-digest.service --no-pager | grep -E "خطا در classification|\[ unknown \]"
  ```
- `sid` هر پست دقیقاً `"{rid}-{date}"` است، همان چیزی که API بله می‌دهد؛ همین
  باعث می‌شود dedup با `news_posts.json` بدون تغییر کار کند و خبری دوباره ارسال نشود.
- برای پاسخ‌دهی ربات در PV، حتماً سرور باید با HTTPS در دسترس باشد.

## ضمیمه‌ها (عکس/ویدیو/صوت/فایل)

پست‌های دارای ضمیمه همراه خلاصه ارسال می‌شوند. چند نکته:

- عکس و ویدیو در API بله هم به شکل `documentMessage` می‌آیند (نه
  `photoMessage`/`videoMessage`)؛ نوع ضمیمه از روی `mimeType` تعیین می‌شود.
- LoadHistory هیچ `file_id` نمی‌دهد — فقط `url` امضاشدهٔ عمومی. پس متد ارسال
  (`sendPhoto`/`sendVideo`/`sendAudio`/`sendDocument`) همان URL را می‌گیرد و
  **خود بله** از آن دانلود می‌کند؛ نه دانلودی سمت ما انجام می‌شود نه آپلودی.
- کپی/فوروارد سمت‌سرور (`copyMessage`/`forwardMessage`) ممکن نیست: ربات به کانال
  مبدأ دسترسی ندارد و `file_id` هم در دست نیست.
- متن خبر بدون خود ضمیمه به مدل می‌رود، ولی مدل می‌داند ضمیمه‌ای هست
  (برچسب نوعش را می‌گیرد) تا خلاصه مثل خبر عادی نوشته شود و مستقیم به
  عکس/فیلم اشاره نکند.
- متن پیام عادی فرستاده می‌شود و فقط خط آخرش عبارت «لینک خبر مرجع» به شکل
  لینک مارک‌داون (`[لینک خبر مرجع](url)`) است؛ بله خودش آن را رندر می‌کند و
  `parse_mode` لازم نیست.
